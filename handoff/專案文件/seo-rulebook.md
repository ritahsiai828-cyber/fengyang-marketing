## 1. 原則（每一條都是硬規則）

1. **不捏造**：數字、價格、行程內容、出發日期、旅客評價、引言、案例，全部只能來自使用者提供的資料、官網實際頁面或有連結的公開來源。查不到就留空或不寫，並在回報裡說明。
2. **目標市場是台灣**：關鍵字、搜尋量、競品、圖片人物都以台灣為準（Ubersuggest 地區 locId 2158、語言 zh）。
3. **一個網址只打一個主關鍵字**，而且要先查到搜尋量才寫。
4. **網址不能用猜的**：所有內部連結、行程頁、商品頁連結都要從 API 或實際頁面確認存在且公開。
5. **改網站前先確認**：除了使用者授權的自動發文排程與指定的修正，其他網站設定、已發布文章的大改，都先問。
6. **全站每天新文章不超過 10 篇**（含所有排程與其他對話發的），避免被 Google 判定為大量生成內容。
7. **發布不等於完成**：發布後要讀回檢查（含格式，見 `claude/blog-format-spec.md`）、送收錄、30 分鐘初檢、1 週完整檢查。
8. **內容定位【待填】**：先跟使用者確認文章要「直接教讀者怎麼做」，還是「點出問題、給考量，解方導向諮詢或報名」。JBS 選了後者：可以寫做法，但用「別人怎麼做＋我們怎麼看」呈現，不對讀者下指令，文末導向課程與詢問。旅行社可能需要實用資訊（例：行李規定、簽證），要跟使用者講清楚哪些可以直接寫、哪些導向諮詢。

## 4. 選題與關鍵字

1. **找候選**：從使用者給的行程與主打產品、季節（連假、寒暑假、旺季）、Search Console 已經有曝光但沒有專文的搜尋字、競品排名好的主題裡挑。
2. **查量**：Ubersuggest `keyword_overview` 或 `keyword_suggestions`（locId 2158、zh）。選「旅客會搜、有對應行程或服務、站上沒有文章在打」的最高量寫法。
3. **網域權重低時**（新站通常是）：優先打月搜尋量 50–500、SEO 難度 ≤ 30 的長尾問句（例：「○○自由行幾天夠」「○○跟團還是自由行」），大詞留到有長尾文章支撐後再打。
4. **比較寫法**：同一個意思比較 2–3 種寫法（例：日本自由行 vs 日本旅遊 vs 日本行程），用量最大的那個，並在標題、首句、H2 用同一個寫法。
5. **查重**：發文前列出全站文章的主關鍵字（Wix 文章 seoData.settings.keywords 裡 isMain 的那個），重複就換。品牌名不要當新文章的主關鍵字。
6. **Ubersuggest 沒數據**：可以用 `google_suggestions` 佐證有人搜，回報時註明「量未知」。
7. **季節性**：Ubersuggest 會給每月搜尋量，旺季前 1–2 個月先寫，Google 才有時間收錄。

競品研究：Ubersuggest `domain_overview`、`domain_keywords`、`domain_top_pages` 可以看台灣競爭對手網站的關鍵字、名次與估計搜尋流量（只算 Google 自然搜尋，是推估值）。要看對手總流量與來源要另接 Similarweb（付費）。

## 5. 文章格式

- **H1 標題**：含主關鍵字的問句。
- **開頭**：2–3 句，第一句是粗體的重點結論（讓 AI 搜尋可以直接引用）。
- **H2**：含關鍵字的問句，不加「一、二、三」編號；H2 下第一句是粗體重點（40–60 字）。
- **段落**：每段最多 4 行；段落、清單、圖片、橫幅之間都要空一行（部落格插入空白段落節點 `{"type":"PARAGRAPH","nodes":[],"paragraphData":{}}`），標題和它的第一段之間不空行，也不要連續空兩行。
- **表格**：只在真的需要對照時用，每篇最多 1 個、最多 4 欄；手機會超出螢幕的不要用。
- **結尾**：H2「常見問題」＋ 2–3 個 H3 題目（不要用摺疊清單，AI 讀不到）。
- **字數**：一般文章 1,200–2,000 字；不灌水。
- **CTA**：文末放行程／商品頁的橫幅或文字連結＋諮詢方式【待填：LINE、電話、表單連結】；優惠碼【待填】。
- **內部連結**：每篇至少 2 篇同主題文章＋1 個行程或商品頁，網址都要確認過。
- **資料來源**：引用的規定、數據、新聞在文末列出來源連結。
- **樣式**：**每個節點都要明確帶樣式**（H2 28px #93616A 行距 2、內文 16px #2D2D2D 行距 2、表格表頭 #A1AEC0 且每格四邊線 #86C6E5、按鈕色碼），完整寫法見 `claude/blog-format-spec.md`，沒帶樣式會跑版。粗體結尾的 `**` 不要緊貼在「。」「？」後面。

### 旅遊業特別注意

- **價格、行程天數、出發日期、團費包含項目**：只用使用者提供或官網行程頁上的資料，文章裡最好不寫具體價格（價格會變），改成連到行程頁。
- **簽證、入境、檢疫、行李規定**：只寫官方來源的重點並附連結（外交部領事事務局、目的地官方網站、航空公司官網），寫上「截至發文日」，不替讀者判斷個案。
- **匯率、天氣、票價**：會變的數字不要寫成定論，寫範圍或連到官方來源。
- **評價與心得**：只用真實的旅客回饋（使用者提供、Google 評論），匿名，不編造。
- **廣告用語**：避免「最便宜」「保證」「第一」這類無法證明的說法（公平交易法、旅行業相關規定）。

## 6. 發布前必填欄位（缺一項就不發布）

| 項目 | 規則 | Wix 欄位 |
|---|---|---|
| 標題 | 含主關鍵字的問句 | title |
| SEO 標題 | 約 25–30 個中文字，主關鍵字在前，後面可加「｜品牌名」 | seoData.tags 裡 type=title |
| meta 描述 | 70–150 字，含主關鍵字 | seoData.tags 裡 meta name=description |
| 主關鍵字 | 1 個，isMain=true，不與其他文章重複 | seoData.settings.keywords |
| 網址 | 短、以關鍵字為主，發布後不改 | seoSlug |
| 摘要 | ≤ 120 字 | excerpt |
| 分類 | 必填【待填：分類清單】 | categoryIds |
| 封面 | 1920×1080、不與其他文章重複；一定要設，否則 Wix 會自動抓內文圖當封面 | media.wixMedia.image＋displayed/custom=true |
| 內文圖 | 1 張，放在第 2 個 H2 下第一段之後，畫面要對應那一段 | richContent IMAGE 節點 |
| Hashtag | 主題詞 | hashtags（見第 8 節的坑） |
| 作者 | 指定的會員 id【待填】 | memberId |

結構化資料：Wix 會自動產生 og 標籤、canonical，也會依「常見問題」的 H3 自動產生 FAQPage。自己寫 JSON-LD 時只放 Organization、BlogPosting、BreadcrumbList，不要再放 FAQPage（否則一頁會有 2 個）。

## 7. 圖片

- **來源優先順序**：使用者的真實照片（Drive）→ 圖庫裡已備好的圖 → Canva 現場生成。不用來源不明的網路圖、圖庫浮水印圖、名人或真實人物照片。
- **畫面**：台灣／東亞人為主角，明亮、主體置中，圖上不放文字；地標景點如果用生成圖，要寫實、不出現品牌標誌與招牌文字。
- **Canva 做法**：generate-image 生圖 → 複製一個 1920×1080 範本設計 → 替換圖片並儲存 → 匯出 JPG → 上傳到 Wix 媒體庫。不要直接用 generate-image 的縮圖（只有約 200px）。
- **圖庫備圖排程**（強烈建議）：Canva 冷卻約每小時 1 張，現場生成會拖住發文。做一個「每小時 1 次」的圖庫排程，照 `image-requests.md` 的「待做需求」提前做圖存進 `image-bank.md`；發文排程每次結束前把下一次要發的題目和畫面描述寫進「待做需求」。
- **alt 文字**：中文描述，含主關鍵字。
- **找不到內文圖**：照常發布，記「缺內文圖」交給補圖排程；**找不到封面就不發布**，存草稿並回報。

## 8. 發布流程（Wix，已實測可用）

1. **建立草稿**：`POST https://www.wixapis.com/blog/v3/draft-posts`，帶 title、memberId、categoryIds、excerpt、media（封面）、richContent（節點樣式照 `claude/blog-format-spec.md`）、seoData。
2. **發布**：`POST https://www.wixapis.com/blog/v3/draft-posts/{id}/publish`，body `{}`。
3. **寫 hashtag（一定要最後做）**：Wix 每次更新內容都會把 hashtag 清空，而且帶 `action: UPDATE_PUBLISH` 或 fieldMask 寫 hashtag 讀回常常是空的。實測有效的做法：
   - `PATCH https://www.wixapis.com/blog/v3/draft-posts/{id}`，body 只帶 `draftPost: { id, memberId, hashtags }`，**不帶 action**；
   - 接著 `POST https://www.wixapis.com/blog/v3/draft-posts/{id}/publish`，body `{}`。
4. **讀回**：`GET https://www.wixapis.com/blog/v3/posts/{id}?fieldsets=CONTENT_TEXT&fieldsets=SEO`，確認標題、SEO 標題、描述、hashtag、封面、段落間距、連結都正確；另讀 RICH_CONTENT 做格式檢查（見 `claude/blog-format-spec.md`「發文後檢查」）。
5. **送收錄**：Wix 的收錄 API 目前只接受首頁，文章頁送了會回 400。把新文章網址列給使用者，請他到 Search Console「網址檢查 → 要求建立索引」手動送。

改已發布的文章：
- 先 `GET /blog/v3/draft-posts/{id}?fieldsets=RICH_CONTENT`，如果 `hasUnpublishedChanges` 是 true，代表有人改了還沒發布，跳過並回報，不要蓋掉別人的修改。
- `PATCH /blog/v3/draft-posts/{id}`，body 帶 `draftPost`（id、memberId、要改的欄位；richContent 要送完整 nodes）＋ `action: "UPDATE_PUBLISH"`；改完照上面第 3 步補回 hashtag。

課程／商品／行程頁連結：用 Wix Stores Catalog V3 查商品的 slug 與 visible，不要用 v1（回 501）。旅行社若用其他方式放行程（CMS 集合、靜態頁），用對應的 API 確認網址存在。

## 9. 發布後檢查與成效

**30 分鐘初檢**（只用 Wix API，不跑爬蟲，省額度）：標題問句、主關鍵字出現在 SEO 標題／H1／描述／首段／H2／alt、H2 無編號、段落間距、連結存在、有 CTA、只有 1 個 FAQPage，**以及格式檢查（H2／內文／表格／按鈕樣式，見 `claude/blog-format-spec.md`）**。只修小問題（描述、alt、編號、破連結、間距、樣式）。

**1 週完整檢查**：
- Google 收錄：用 Wix 的 Search Console 網址檢查看是否「已建立索引」；沒收錄就列給使用者手動送。
- 排名與點擊：Search Console 成效 API（見下）。
- 可以補 1 題 FAQ 或內部連結；不改網址、不改事實、不整篇重寫，大改只提建議。

**Search Console 成效（透過 Wix，已實測）**：
```
GET https://www.wixapis.com/gsc/v1/site-readiness
GET https://www.wixapis.com/gsc/v1/search-analytics?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&dimensions=page&rowLimit=500
```
- dimensions 可用 date、page、query、country、device，可以兩個一起（例：page＋query 看每篇文章被什麼字搜到）。
- 回傳 clicks、impressions、ctr、position；網址是百分比編碼，要解碼成中文。
- 資料約晚 2 天。
- **最有用的判讀**：曝光 ≥ 50、平均排名 ≤ 10、點擊率 < 2% 的文章，代表排名不差但標題描述沒吸引力，看它實際被搜的字，改 SEO 標題與描述去對應搜尋意圖（但標題不能承諾文章裡沒有的內容）。排名 8–20 名的字，補內容或內部連結最容易推上第一頁。

## 10. 排程設計

建議的排程（時間依網站流量與使用者作息調整；整點容易延遲，用 :07、:23 這類分鐘）：

| 排程 | 頻率 | 做什麼 |
|---|---|---|
| 每日發文 | 每天 1 次 | 依主題輪替發 N 篇（先數當天全站已發篇數）；用圖庫的圖；結束前寫隔天的待做需求 |
| 圖庫備圖 | 每小時 | 照待做需求做圖；沒有需求時補少量通用圖 |
| 發布後初檢 | 每天 2–4 次 | 檢查過去幾小時新發的文章（含其他對話發的） |
| 1 週完整檢查 | 每天 1 次 | 檢查發布滿 7 天的文章 |
| 補圖 | 每晚 1 次 | 補「缺內文圖」的文章 |
| 漏發補發 | 每天 1 次 | 帳號使用量用完時排程會整天失敗、不會自動重試；漏掉的文章記在 catchup-log 由這個排程補 |
| 每日晨報 | 每天早上 | 只讀不改：昨天每個排程有沒有發出、缺圖、全站篇數、今天預計發什麼、要手動送收錄的網址 |
| 週報 | 每週一 | 產量、Search Console 點擊曝光排名、點擊率低要改標題的文章、下週目標 |
| 月報 | 每月 1 日 | 月總結、各系列成效、下個月優化方向（只提建議） |

設計原則：
- **同一件事只由一個排程做一次**：例如結構化資料只在初檢補一次、Ubersuggest 爬蟲只在 1 週檢查跑，發文排程不重複做。
- **排程提示寫「先讀規範」**，規則放規範裡；不要在提示裡呼叫 list_triggers 讀其他排程（很耗額度）。
- **每個排程都要能獨立執行**：提示寫完整，包含網站 id、要讀哪些文件、不可以做的事、回報格式。
- 排程會自動執行、不等核准，所以「不可以做」要寫清楚（例：不改網站設定、不刪文章、不在社群發文）。

## 11. 常見錯誤（JBS 實際發生過）

- 多篇文章主關鍵字都打同一個詞，互相搶排名 → 發文前一定查重。
- 自己在 JSON-LD 放 FAQPage，加上 Wix 自動產生的，一頁 2 個 → 自己不放。
- 修改文章後 hashtag 被清空 → 一律最後用第 8 節第 3 步補回並讀回。
- 先發布、後補封面，Wix 自動抓內文圖或橫幅當封面 → 發布前一定設封面。
- 段落沒有空行，手機很難讀 → 每個內容區塊之間一個空白段落。
- 表格太多太寬，手機跑版 → 每篇最多 1 個。
- 節點沒帶樣式（標題、內文、表格線條）造成跑版 → 照 `claude/blog-format-spec.md` 明確寫樣式，發文後讀回檢查。
- 紀錄文件寫到 10 萬字，每個排程讀寫都很貴、還會被截斷 → 照第 3 節精簡。
- 一天發太多（曾經一天 30 多篇）→ 每個發文排程先數當天全站篇數。
- 帳號使用量用完，所有排程整天失敗 → 晨報會發現；補發排程分天補。
- Canva 冷卻導致缺圖不發文 → 圖庫提前備圖。
- 收錄 API 只接受首頁，新文章一直沒被 Google 發現 → 每天把新網址列給使用者手動送收錄，大量發文後重新提交 sitemap。
- 商品頁連結用 Stores v1 驗證回 501 → 用 V3。
- 用搜尋 API 找商品時只看前幾筆，拿錯商品 → 列出全部後比對 slug。

## 12. 第一次設定清單

1. 跟使用者確認並填好所有【待填】：網站平台與網站 id、作者 memberId、分類、CTA 與諮詢連結、優惠碼、內容定位、每天發幾篇與主題輪替。
2. 用 Wix 列出現有文章，建立 `keyword-ledger.md`（每篇主關鍵字＋網址）與 `seo-check-log.md`。
3. 確認 Search Console 狀態：`GET /gsc/v1/site-readiness` 回 READY；拉一次過去 28 天 dimensions=page 與 query，找出已有曝光的主題與點擊率低的文章，當第一批選題與優化清單。
4. 用 Ubersuggest 查 3–5 個台灣競品網域的熱門關鍵字與頁面，補進選題清單。
5. 在 Canva 準備一個 1920×1080 範本設計，記下設計 id。
6. 先手動發 1 篇，照第 8、9 節完整走一次並讀回，確認每一步都能用，再建立排程。
7. 建立第 10 節的排程，先開每日發文、初檢、晨報，穩定一週後再加補發、週報、月報。
